## Knowledge management (firm rule)

- **Zero external memory.** All knowledge — user inputs and assistant decisions — lives in **flat,
  versioned files in this repo**. Canonical stores: `README.md` (business context), this `CLAUDE.md`,
  `.claude/settings.json`, OpenSpec specs under `openspec/`, and `docs/`.
- Structural decisions → `docs/adrs/` (numbered ADRs). Reusable recipes → `docs/playbook/`. Agentic
  build narrative (basis for articles) → `docs/build-log.md`.

## Architecture & conventions

- **Two self-contained ecosystems**, each extractable to its own repo: `frontend/` (TS/React/Astro)
  and `backend/` (Python/FastAPI, skeleton in Lot 1). No build dependency between them; the only
  cross-boundary contract is the **HTTP API** (Pydantic v2 → OpenAPI), introduced in later lots.
- **Content/presentation decoupling** (frontend): content is **YAML data** under `frontend/content/`,
  validated by Zod (fail-fast); React/Astro components are **content-agnostic** (data passed as
  props); a **block registry** maps a content `type` to a component. Adding/removing an experience or
  media = edit a YAML file only; a new block layout = a new component.
- **Component library**: all React components live in `frontend/packages/ui` (`@gmocquet/ui`),
  consumed only via its public API — never its internals.
- **i18n**: EN YAML is the source of truth; FR YAML is generated by the idempotent translation CLI
  (`frontend/tools/i18n/`); manual FR edits are overwritten when the EN source changes.
- Future: per-ecosystem `frontend/CLAUDE.md` / `backend/CLAUDE.md` may be added when ecosystems are
  extracted (Claude Code auto-loads the nearest `CLAUDE.md`).

## Task runner (harmonized)

The root **`Makefile`** is the single entry point; targets are **one-liners** delegating to
`scripts/` or ecosystem tooling (no business logic, no block > 5 lines in the Makefile). Local and CI
call the **same** `make` targets (single source of commands → reproducibility). `make help` lists
them. `scripts/` holds the testable implementations (`doctor.sh`, `github-bootstrap.sh`, …).

## Expert agents (`.claude/agents/`)

- `frontend-ux` — frontend ecosystem (Astro/React/UX/UI, perf, `packages/ui`).
- `infra-cloud` — Cloudflare Pages, DNS OVH→Cloudflare, GitHub Actions, IaC.
- `backend-python` — backend ecosystem (FastAPI/Pydantic v2); skeleton now, owner of Lot 2.

Dispatch agents in parallel where steps are parallelizable; the main thread orchestrates and
integrates.

## Workflow

- **Every change via a Pull Request**; never push directly to `main`; never merge a PR automatically
  (the user merges).
- **Conventional Commits** mandatory (drive semver tagging + `CHANGELOG.md`).
- GitHub auth is **SSH** (remote `git@github.com:…`); `gh` is used for governance (issues,
  milestones, board, PRs) — see `scripts/github-bootstrap.sh`.
- Anthropic auth defaults to **OAuth** (no AI credential in `.env`); an API key is an optional
  fallback loaded from `.env` (via `.envrc` / direnv).
- Definition of Done: tests pass, docs/specs updated (incl. `README.md`), lint/format/hooks clean.
