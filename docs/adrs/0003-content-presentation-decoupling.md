# 0003 — Content/presentation decoupling (YAML + Zod)

- **Status**: Accepted (2026-06-20)

## Context

The owner must be able to add/modify/remove experiences, projects and media by editing **data only**,
without touching React/HTML/CSS, and self-serve without asking the assistant.

## Decision

Store content as **human-friendly YAML** under `frontend/content/` (first-class in the Astro content
layer). Validate it with **Zod schemas** in `frontend/src/content.config.ts` (**fail-fast** at build).
Keep components **content-agnostic** (data passed as props); a **block registry** maps a content
`type` to a component. EN YAML is the source of truth; FR YAML is generated by the idempotent
translation CLI (manual FR edits are overwritten when the EN source changes).

- Add/modify/remove an entry = edit one YAML file → zero component change.
- A new block layout = a new component registered in the registry (the only time code changes).

## Consequences

- Self-service content editing; data is portable (could feed another frontend or a future CMS).
- Requires discipline: components never embed content; the schema is the contract.
